# CICLO 테마

Elementor · WPCode · 페이지빌더 **없이** 도는 자체 테마입니다.

> 이 파일은 `theme-README.md` 가 원본이고 `build-theme.py` 가 테마 폴더로
> 복사합니다. 고치실 때는 원본을 고치세요.

---

## 설치 — 세 단계

### 1. 테마 올리기

`ciclo-theme.zip` → 외모 > 테마 > **새로 추가** > **테마 업로드** > 지금 설치하기
→ **활성화**

### 2. 페이지·카테고리 가져오기

도구 > **가져오기** > WordPress > 실행 > `ciclo-import.xml` 선택

- 작성자는 본인 계정으로 지정
- "첨부 파일 내려받기"는 **체크하지 않아도 됩니다**

만들어지는 것: 페이지 10개 · 칼럼 카테고리 7개 · 확인용 샘플 글 1편

### 3. 홈 지정

설정 > **읽기** > "홈페이지 표시"를 **정적인 페이지**로

| 항목 | 지정 |
|---|---|
| 홈페이지 | **홈** |
| 글 페이지 | **— (비워 둠)** |

> ⚠️ **글 페이지에 "칼럼"을 지정하지 마세요.**
> 지정하면 워드프레스가 `page-column.php` 대신 글 목록 템플릿을 씁니다.
> 칼럼은 그냥 페이지로 두면 `/column/` 에서 목록이 나옵니다.

끝입니다. `ciclo.kr/` 을 열어 확인하세요.

## 페이지 본문이 비어 있는 게 정상입니다

가져오기로 만들어진 페이지 10개는 **내용이 없습니다.** 디자인과 문구는 전부
테마의 `*.php` 안에 있고, 페이지는 주소를 만들어 주는 껍데기입니다.

이게 이 구조의 핵심입니다. 예전에는 마크업이 Elementor 의 `_elementor_data`
JSON 안에 이스케이프돼 들어가 있어서, 문구 하나 고치려면 JSON 을 다시 만들고
가져오기를 다시 해야 했고 그때마다 기존 편집이 날아갔습니다.

**슬러그가 템플릿을 정합니다.** 슬러그를 바꾸면 그 페이지만 디자인이 빠집니다.

| 페이지 | 슬러그 | 템플릿 |
|---|---|---|
| 홈 | `home` (설정>읽기에서 홈 지정) | `front-page.php` |
| Work | `work` | `page-work.php` |
| About | `about` | `page-about.php` |
| Contact | `contact` | `page-contact.php` |
| 칼럼 | `column` | `page-column.php` |
| Website Design | `website-design` | `page-website-design.php` |
| GEO | `geo` | `page-geo.php` |
| Blog Content | `blog-content` | `page-blog-content.php` |
| Digital Marketing | `digital-marketing` | `page-digital-marketing.php` |
| 치과 홈페이지 제작 | `dental` | `page-dental.php` |

## 내용을 고치려면

| 무엇 | 어디 |
|---|---|
| 홈·서브페이지 문구 | 해당 `*.php` (마크업이 그대로 들어 있습니다) |
| 색 · 타이포 · 여백 | `assets/css/global.css` |
| 사이드바 동작 · 현재 페이지 표시 | `assets/js/ciclo-effects.js` |
| **칼럼 글** | 워드프레스 글쓰기 (평소대로) |
| 칼럼 카테고리 메뉴 | `functions.php` 의 `ciclo_column_cats()` |

파일 수정은 외모 > **테마 파일 편집기**에서도 되고, FTP 로 올려도 됩니다.

## 켠 뒤 확인

| 확인 | 정상이면 |
|---|---|
| 홈 | 네이비 `CICLO.` + "GEO 웹사이트, 랜딩페이지 제작" |
| 홈 F12 > Console | 빨간 에러 0개 |
| **`/column/`** | 샘플 글 1편이 썸네일 없이 제목·요약·날짜로 |
| **샘플 글 클릭** | 제목 · 본문 · 인용 · 표 · 이전다음 |
| 카테고리 메뉴 | 클릭하면 해당 분류만 |
| 휴대폰 `/dental/` | 옆으로 밀리지 않음 |
| F12 > Network > CSS | 스타일시트 **2장** (Pretendard + global.css) |

> ★ **칼럼 두 화면을 먼저 봐 주세요.**
> 나머지 페이지는 브라우저 실측으로 검증했지만, 칼럼 목록과 글 상세는
> 플러그인을 걷어내면서 **새로 쓴 것**이라 실제 글로는 확인하지 못했습니다.
> 그래서 가져오기 파일에 샘플 글을 한 편 넣어 뒀습니다. 확인 뒤 지우세요.

## 이 구조가 없애는 것

| 예전 | 지금 |
|---|---|
| 층 4개 (Hello Elementor → Elementor → WPCode → 커스터마이저) | 테마 하나 |
| 25KB 중복 CSS 가 특정성으로 원본을 이김 | CSS 한 곳 — 구조적으로 발생 불가 |
| 커스터마이저 820px 가 홈까지 누름 | 그런 규칙 없음 |
| JS 스니펫 하나 죽으면 사이트가 죽음 | 정상 enqueue |
| Elementor 호환 CSS · 빌더 유틸 · 테마 브랜딩 **36개 규칙** | 삭제 (−5.2KB) |
| 플러그인 클래스에 `!important` 21개 | 삭제 |
| Elementor + Essential Addons 전역 로딩 | 없음 |

`global.css` 는 gzip 기준 원본 대비 **28% 작습니다**.

## 검증한 것과 못 한 것

**검증**

- PHP 문법 — 18개 파일 `php -l` 전부 통과
- 템플릿 실행 — 워드프레스 함수를 스텁으로 채워 15개 템플릿 실제 실행,
  Fatal error 0건 (`../tools/render-theme.php`)
- 출력 HTML — doctype · `</html>` · body 1 · main 1 · h1 1 · PHP 잔존 0
- 브라우저 (1440 / 390) — 가로 넘침 0 · 겹침 0 · CLS 0 · JS 에러 0 ·
  대비 AA 미달 0
- 가져오기 XML — XML 파싱 OK · 슬러그 중복 0 · 템플릿과 1:1 대응 확인

**못 한 것 (워드프레스가 없어서)**

- 템플릿 계층이 실제로 `page-work.php` 를 고르는지 — 규칙은 표준입니다
- 실제 DB 로 도는 칼럼 루프 — 가짜 글로 대신했습니다
- 가져오기 도구가 이 XML 을 실제로 삼키는지 — 구조는 WXR 1.2 표준입니다
- 다른 플러그인(SEO · 폼 · 캐시)과의 충돌
